# 2048 게임 구현 계획서 (spec)

## 1. 앱 개요와 기능 목록
방향키(또는 스와이프)로 숫자 타일을 밀어 같은 숫자끼리 합쳐 2048 타일을 만드는 퍼즐. `/apps/2048/` 안에서 자체 완결(블로그 다른 파일 미수정), 외부 라이브러리 없음.

- **보드**: 4x4. 시작 시 타일 2개 생성.
- **이동/합치기**: 한 방향으로 모든 타일을 끝까지 밀고, 인접한 같은 값 두 개는 하나로 합쳐 2배가 된다. 한 이동에서 한 타일은 한 번만 합쳐진다 (예: `[2,2,2,2]` 좌 -> `[4,4,0,0]`, `[2,2,4,0]` -> `[4,4,0,0]`).
- **새 타일**: 이동으로 보드가 실제로 변했을 때만 빈 칸 무작위 1곳에 생성 (2: 90%, 4: 10%).
- **점수**: 합쳐질 때마다 생성된 타일 값만큼 현재 점수 가산.
- **최고 점수**: 현재 점수가 넘으면 갱신, `localStorage`(키 `2048-best`)에 저장. 접근 실패 시 try/catch로 메모리만 사용.
- **승리**: 2048 타일 최초 생성 시 "승리" 오버레이 + "계속하기"(이후 계속 플레이) / "새 게임".
- **게임오버**: 빈 칸이 없고 인접한 같은 값이 없으면 오버레이 표시.
- **새 게임 버튼**: 보드·점수 초기화 (최고 점수 유지).

## 2. 입력 방식
- 방향키 ←↑→↓ 및 WASD. 방향키는 `preventDefault()`로 페이지 스크롤 방지.
- 터치 스와이프: 보드에 `touchstart`/`touchend`, 이동량 임계값 약 30px, 가로/세로 중 큰 축으로 방향 결정. 보드에 `touch-action: none`으로 스크롤 충돌 방지.
- 오버레이 표시 중에는 이동 입력 무시.

## 3. 파일 구조
```
apps/2048/
├── index.html   # 시맨틱 마크업: 헤더(제목, 점수판, 새 게임 버튼), 보드 컨테이너, 오버레이, 안내문. viewport meta, lang="ko"
├── style.css    # CSS 변수(색상), 보드 그리드, 타일 색상, 반응형, 다크 모드, 애니메이션
├── game.js      # 순수 게임 로직 (DOM 비의존): 보드 상태, slide/merge, 이동 가능 판정, 점수
├── ui.js        # 렌더링, 입력(키보드/터치) 바인딩, localStorage, 오버레이 제어 (ES module, game.js import)
└── spec.md      # 본 문서
```
`index.html`은 `<script type="module" src="ui.js">`로 로드. (file:// 에서 모듈이 막히므로 정적 서버로 확인.)

## 4. 핵심 로직 설계
- **보드 표현**: `number[4][4]`, 0은 빈 칸. 상태 `{ board, score, best, won, over }`.
- **한 줄 처리 `slideLine(line) -> { line, gained }`** (왼쪽 기준):
  1. 0 제거해 압축 -> 2. 앞에서부터 인접한 같은 값 병합(병합된 칸은 건너뜀), `gained += 합` -> 3. 0으로 길이 4까지 패딩.
- **방향 처리**: 좌는 행 그대로, 우는 행 reverse 후 처리 뒤 reverse, 상/하는 전치(transpose) 후 좌/우로 처리하고 다시 전치. 방향별 중복 구현을 피한다.
- **변화 감지**: 이동 전후 보드를 비교해 달라졌을 때만 새 타일 생성·점수 반영.
- **이동 불가 판정 `canMove(board)`**: 빈 칸이 있으면 true; 없으면 가로/세로 인접 쌍 중 같은 값이 있는지 검사. false이면 게임오버.
- **승리 판정**: 이동 후 2048 이상 타일 존재 && 아직 `won` 아님 -> `won = true`, 오버레이.
- **애니메이션용 정보**: 타일에 id 부여하여 이동/병합/신규 여부를 UI에 전달 (신규=팝, 병합=펄스).

## 5. UI/디자인
- **레이아웃**: 보드는 정사각형, `width: min(92vw, 28rem)`, CSS Grid 4x4, 간격 약 0.6rem. 좌우 여백 최소 16px, 가로 스크롤 없음, 새 게임 버튼 터치 영역 44px 이상.
- **색상**: 모두 CSS 변수. 값별 타일 색상(2~2048, 이후 단일 어두운 색), 2·4는 어두운 글자, 8 이상은 밝은 글자 (대비 WCAG AA 지향). 큰 숫자(≥128)는 글자 크기 축소.
- **다크 모드**: `prefers-color-scheme` 자동 대응(변수 재정의). 수동 토글은 범위 외.
- **애니메이션**: 가벼운 수준 — 타일 이동 transform transition(약 100ms), 신규 타일 scale 팝, 병합 시 짧은 펄스. `prefers-reduced-motion`에서는 비활성화.
- **접근성**: 버튼 `aria-label`, 점수판 `aria-live="polite"`, 오버레이 `role="dialog"`.

## 6. 검증 체크리스트 (Review용)
- [ ] 시작 시 타일 2개, 값은 2 또는 4
- [ ] `[2,2,2,2]`->`[4,4,0,0]`, `[2,2,4,0]`->`[4,4,0,0]`, `[4,2,2,0]`->`[4,4,0,0]` 등 4방향 모두 정확
- [ ] 변화 없는 이동에는 새 타일 생성·점수 변화 없음
- [ ] 합칠 때 점수가 정확히 가산됨, 새 게임 시 0으로 초기화
- [ ] 최고 점수가 갱신되고 새로고침 후에도 유지, localStorage 차단 환경에서도 오류 없음
- [ ] 2048 생성 시 승리 오버레이, "계속하기"로 진행 가능
- [ ] 빈 칸 없고 병합 불가일 때 게임오버, 병합 가능하면 게임오버 아님
- [ ] 방향키 입력 시 페이지 스크롤 없음, WASD 동작
- [ ] 터치 스와이프 4방향 동작, 보드 위 스와이프 시 페이지 스크롤 안 됨
- [ ] 375px 폭 및 데스크톱에서 레이아웃 정상, 가로 스크롤 없음
- [ ] 라이트/다크 양쪽에서 타일 글자 대비 충분
- [ ] 외부 라이브러리·CDN 미사용, 콘솔 에러 없음, `apps/2048/` 밖 파일 미수정
